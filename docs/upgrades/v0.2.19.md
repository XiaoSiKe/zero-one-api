# v0.2.19 integration and release contract

This document records the first v0.2.19 Backend release and its evidence. The UI deferral described below is superseded by the separately reviewed [management UI delivery](v0.2.19-admin-ui.md) and [ADR 0022](../adr/0022-v0219-management-ui.md); the original integration counts and test history remain unchanged.

The Upstream Baseline is `v0.2.19` at `dece26153621959ccd7635814f4b2d08304e681a`, published on 2026-10-28. The previous baseline is v0.2.17, so this update also includes v0.2.18. The pre-upgrade product is `745defbae917f6d405dcfa09f7b32cda5d082c85`; the two-parent integration is `e014afda192b885bfc4054a7b2d3a84479ca1841`. The reproducible [change map](v0.2.19-change-map.json) covers 353 upstream paths: 252 adopted, 57 adapted and 44 frontend paths with production delivery deferred.

## Integration and preserved behavior

Scoped Administrator API Keys use the upstream permission catalogue, resource checks, irreversible key hashes, expiry, IP restrictions and audit records. Key lifecycle operations require an Administrator JWT and the existing step-up policy. Unregistered product actions remain denied to scoped keys; Affiliate Attribution's manual binding remains JWT-only.

Image billing remains owned by the existing billing resolver. The new Group image-count switch defaults to false and only affects dedicated OpenAI/Composite image endpoints when explicitly enabled. Preserve generic gpt-image-2.5, image model identity, historical customer charges and request-time upstream cost evidence. Gemini fileData images and DeepSeek cache reads now enter the upstream accounting corrections. Explicit cache identity and the cache_storage evidence boundary remain unchanged.

The Anthropic compatibility stream owner drains accepted usage after client disconnection with a bounded timeout. Both successful and partial-error handler paths freeze Site First Token and channel usage fields before submitting the existing billing task. First metadata, pings and empty deltas still do not count as visible output. Product-specific OpenAI conversion paths call the shared interval function directly. The authentication snapshot adds image-count billing while retaining the product's deep copies of pricing, allowlists and model manifests.

The approved Landing, Console source and published static assets are preserved. API clients and shared types adopt compatible additions; the new scoped-key management, Grok diagnostics and image-count configuration UI are deferred. [The key guide](../admin-api-keys.md) explicitly distinguishes the upstream UI instructions from the APIs currently delivered by Zero One. Retired duplicate editors and Channel Monitor V2 remain absent. VERSION is explicitly 0.2.19 because the upstream tag still contains 0.2.18. Go 1.27.3 is consistent across module, image builds and CI; the product's newer x/image security version is retained.

Security maintenance updates DOMPurify to 3.4.17, frontend Vite to 6.4.4, Landing Vite to 8.2.4, Vitest/coverage to 4.1.12 and follow-redirects to 1.16.1. These source/build dependency changes do not replace published production assets. The former braces advisory [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) was withdrawn on 2026-10-23; its unused audit exception is removed. The existing bounded parser patch and its regression remain independent build hardening. The Redeem Code schema comment now agrees with the enforced claim-preservation contract; claimed records cannot be removed by management.

## Data and release acceptance

Preserve the complete original migration ledger and apply the unmodified upstream migrations 246, 247 and 248. Migration 247 adds scoped_admin_api_keys; migration 248 adds groups.image_count_billing=false. Migration 246 changes allow_image_generation from false to true only for Gemini/Antigravity Groups. Those paths previously had no image-generation gate; this migration preserves their effective image access when the new explicit gate starts enforcing the flag. OpenAI, Grok and Composite permissions remain unchanged. Subsequent Administrator changes to the new Gemini gate are authoritative.

The release controller projects exactly migration 246's permitted pre-migration values before comparing all original rows and columns. It does not omit the permission column or accept other changes. A real isolated PostgreSQL regression compares both flag values across five platforms, verifies repeatability and rejects an unrelated permission change. Migration 239's existing pricing projection and derived monitor watermark exclusions remain unchanged. No balances, API Keys, claims, historical bills or business secrets may be rewritten.

Before cutover, restore fresh encrypted off-host PostgreSQL, Redis and deployment-state archives into an isolated populated environment. Exercise migration-only repeatability and new/old/new image compatibility, verify original data under the exact migration projection, constraints, sequences and financial totals. Repeat the restore against the final drained snapshot. Preserve production PostgreSQL/Redis container identities, mounts, business secrets and the direct tunnel.

Require complete make test, source and frozen compatibility builds, repository/deployment/security checks and pinned Linux Chromium before PR publication. Require protected PR checks and exact-main product/security evidence before building immutable same-SHA Backend/Edge images. Deploy through release-control.py in Backend-first order with its watchdog, verified final backup, rollback path, dedicated smoke identity and at least 30 minutes of observation. Actual test, restore, cutover and production outcomes must be recorded from execution; planned checks are not passed evidence. Recovery material and credentials stay outside Git.
