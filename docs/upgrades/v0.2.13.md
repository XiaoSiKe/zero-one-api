# v0.2.13 integration and release contract

The Upstream Baseline is `v0.2.13` at `3040209f205472038c1ba745a1bedd2edd9053b1`. The pre-upgrade product is `6db1a2d0d1a5ca88f62623e03285d21ea745f5e8`; the two-parent merge is recorded in `.github/upstream-baseline.json`. The deterministic [change map](v0.2.13-change-map.json) covers all seven upstream paths since v0.2.12. This target stays fixed throughout verification and publication.

## Integration ownership

The usage billing repository now tolerates an API Key disappearing before settlement: its own quota and rate counters are skipped while user balance, subscription, account quota and request deduplication remain transactional. Other database errors still abort the transaction. This changes future settlement only; historical bills and balances are not recalculated.

The existing upstream billing probe identity catalog accepts TypeSafe API Key accounts. Official `typesafe.ai` endpoints are marked unsupported without a probe request, just like other official providers; relay endpoints retain the existing probe flow. The product's request-time declared account cost, platform catalog, access controls and TypeSafe conversational-monitor exclusion remain intact. No parallel billing or account-creation path is introduced.

The upstream security policy is retained as upstream reporting guidance. The Approved UI Snapshot and every published asset namespace remain byte-identical. VERSION is aligned to 0.2.13 because the upstream tag still contains 0.2.12; the managed version badge remains informational.

## Build dependency security

GHSA-vfj7-8cjw-p6xm was reviewed on 2026-10-02 and affects the existing braces 3.0.3 build dependency; no registry fix is available. A pnpm patch caps parser nesting and every recursive AST walker at 128 levels, including caller-provided ASTs. Real micromatch callers and normal expansion remain covered by regression tests. The security workflow requires these tests before accepting the exact advisory exception, which expires on 2026-10-17. The raw audit still reports the package version; this is a verified local mitigation, not a claim of an upstream patched release or zero advisories. Replace the patch and remove the exception when a fixed release is verified. Both supported frontend Docker build stages copy the patch before frozen dependency installation. The supported deployment builder raises its Node heap cap from 1536 to 3072 MiB after the complete Vue typecheck exhausted the old cap; this is a build-stage limit only. Landing Vitest is pinned to 4.1.11 to remove GHSA-82fw-gwwq-j7x9 from the separate test toolchain.

## Data and rollback

There are **no new migrations**. Preserve the complete full-filename migration ledger, every existing business column, all serial sequences, credentials, financial records and runtime secrets. Verify an encrypted off-host restored production database with migration-only twice and new/old/new application compatibility before cutover. Compare the final stopped-write snapshot with the upgraded database and keep PostgreSQL/Redis container identities and mounts unchanged.

Use the existing release controller, watchdog, Backend-first paired immutable images, dedicated model probes and at least 30 minutes of observation. Application rollback retains the database and all newly accepted writes; an old dump must never overwrite them. Recovery archives and signing/encryption keys stay outside Git.

## Acceptance

Run complete `make test`, product-policy and upgrade-readiness checks, source build, frozen-generation, deployment/routing, security and Chromium gates. Require protected PR checks and exact-main product/security evidence before publishing same-SHA multi-architecture images. Signed restore, cutover and observation evidence belongs in this release's restricted recovery directory; a planned check is not a passed check.
