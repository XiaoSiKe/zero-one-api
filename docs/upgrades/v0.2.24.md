# v0.2.24 integration contract

Zero One integrates [Sub2API v0.2.24](https://github.com/Wei-Shaw/sub2api/releases/tag/v0.2.24) at `5c2982a81b46e2142d0143d2f83c1ce9c4da1d24`, including v0.2.22 and v0.2.23. The [change map](v0.2.24-change-map.json) records the two-parent integration against v0.2.21. The tagged source reports 0.2.23, so Zero One sets the server version to 0.2.24.

## Gateway and billing

- Apply the upstream duplicate-field rejection and protocol-specific request limit handling across the gateway routes. Clients must send each field once. Retain Site First Token timing at the flush of complete visible output, with separate Attempt First Token timing for Provider Account scheduling.
- Adopt upstream stream failover, token rotation, request accounting, and scheduler updates. Anthropic responses continue to share one buffered assembler with the updated cache-write TTL accounting.
- Use customer debits for actual spending in model and endpoint statistics, including when filtered by Provider Account. Report the account cost separately from request-time evidence and keep it unknown when the evidence is incomplete.
- The Gateway supports GPT-6.2 Sol and Astra, Ultra Fast policy and pricing, Gemini Carbon and Vertex multi-region routing, and Exa for search emulation. The auth snapshot moves to version 29 to carry the new forced service tier alongside existing privacy and pricing fields.

## Console and migrations

The production Edge continues to serve the Approved UI Snapshot. The maintained Vue source includes compatible upstream updates to account, group and channel forms. Use the corresponding admin APIs for newly introduced settings that the recovered Console does not expose.

The migration ledger uses complete filenames. The two `251` migrations add a disabled-by-default group Ultra Fast flag and allow group usage rollup rebuilds to proceed concurrently with usage recording. Migration `252_channel_pricing_ultrafast_multiplier.sql` adds a nullable channel multiplier. It uses model defaults when unset. Existing usage rows keep their recorded billing and account-cost evidence.

Any future production release follows the [coherent release procedure](../OPERATIONS.md#release-and-rollback).
