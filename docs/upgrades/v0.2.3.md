# v0.2.3 integration and release contract

The upstream baseline is `v0.2.3` at `8fa67d477d6651a744754392a8982ea589c26ae6`.
The pre-upgrade product is `e9c6d86dc25bdd269c12965227263e19aac8bdb3`.
The recorded two-parent merge is `25ec6609100ec10d4724ae4a7fe1d20614be4c4b`;
it preserves every path protected by the pre-upgrade registry. The per-path
integration disposition is recorded in `v0.2.3-change-map.json`.

## Integration decisions

- Adopt the upstream group model allowlist, gateway admission, auth snapshot v24,
  pricing-time fixes, Ollama Cloud fixes, payment fulfilment isolation and the
  remaining v0.2.2/v0.2.3 corrections.
- Preserve the Approved UI Snapshot, simple-mode boundaries and product routes.
  The model-list editor moves to `model_allowlist`; previously hidden advanced
  group controls remain hidden.
- Restore native historical account cost throughout administrator reports. Keep
  upstream declaration evidence and old aggregate columns for compatibility,
  but do not use them as the current report authority.
- Show total users as the dashboard user headline and add actual-consumption and
  total-token trends under the existing date and granularity controls.

## Migrations and rollback

The new migration filenames are:

- `235_group_model_allowlist.sql`
- `236_group_model_allowlist_repair.sql`
- `237_group_model_allowlist_compat.sql`

Migration 237 recreates `models_list_config` as a synchronized rollback mirror.
Both old-only and new-only writes update the other column; conflicting dual
writes fail. The release restore drill must run both the target image and the
actual pre-release image against the migrated populated database.

No existing group is opted into allowlist enforcement by this migration. Usage,
balances, redeem claims, subscriptions and affiliate records are not rewritten.

## Release evidence

Run the complete backend, Console, Landing, routing, migration, security and
visual suites. Publish Backend and Edge only from the merged main SHA. Before
cutover, restore the encrypted production backup in isolation, verify the three
new migration filenames and both compatibility columns, then follow the existing
backend-first release controller and 30-minute observation gate.

The guarded test-user cleanup is a separate post-release operation. It may delete
only IDs 300 and 302 after its dry-run proves the exact source fingerprint, zero
business value and zero references.
