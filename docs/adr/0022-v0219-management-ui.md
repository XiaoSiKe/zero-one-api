# ADR 0022：v0.2.19 管理功能进入现有 Console

状态：已接受。用户明确要求补齐上次暂缓的上游管理功能，并保留零一现有风格与二开合同。本次属于单独验收的 Console 发布，遵循 ADR 0004 的视觉审核与不可变资源边界。

## 界面与责任

- 系统设置的安全页签交付受限 Administrator API Key 的权限目录、资源规则、有效期、IP 限制和创建／编辑／启停／轮换／撤销／移除记录。密钥生命周期仍由既有服务端、JWT Administrator 与 step-up 策略授权。完整密钥只保存在当前组件内存；离开安全页签或关闭展示后消失。
- Grok 模型目录诊断进入 `EditAccountEditorPanel`。公开 `EditAccountModal`／`CreateAccountModal` 保持兼容包装，不能恢复上游单体弹窗或已退役组件。模型来源、时效、最近尝试和本地映射差异均使用已上线 API；诊断读取不能自行重写映射。
- OpenAI／Composite 的按张计费控件由共享分组编辑表单定义一次，create/update 各自提交并回读既有 `image_count_billing` 字段。关闭生图或切换不支持的平台时归零，默认不开启；不调整现有分组、价格或历史账单。
- 同步管理页的渠道 Web Search 平台配置、服务账号额度能力与模型候选，保留产品的账号成本证据、权限、邀请码、兑换、导航和自定义页合同。

## 生产交付

`cn-provider-admin-v11` 从维护中的 Vue 源码生成，统一拥有现有管理路由和 `/admin/settings` 的路由内容。沿用现有只读鉴权／语言快照、Router 上下文、Toast、导航协调器和 `main` 内挂载位置，不增加第二套 AppLayout、鉴权刷新定时器或全局导航观察器。

`cn-provider-shell-v12` 继承固定的 v10 外壳，只增加既有 v11 账号成本可见性运行时和 Settings 的惰性占位路由。原 v11 包及其他已发布资源保持 URL 和字节不变，不能覆盖缓存中的旧入口。

新外壳使用独立的 `password-recovery-v7` 绑定同一套 Vue、Router、Pinia 与 API 实例；只重映射 v6 的固定模块引用，不改历史认证资源。导航运行时 `zero-one-header-custom-menu-v2.js` 继续负责外壳导航，但检测到源码 Settings 时跳过旧表单注入与请求重写，防止重复控件和错误索引。

Settings 由维护中的 `SettingsView` 拥有完整保存与辅助设置协调。新入口停止加载旧 `zero-one-settings-unified-save-v1.js` DOM 补丁，防止两个 owner 重复提交辅助配置；旧文件保留供历史入口与回滚使用。顶部自定义菜单、二维码、侧栏排序等仍沿用现有接口和协调器。

## 验收与数据

验收必须覆盖实际交付的浏览器入口：受限密钥生命周期与保守授权默认值、step-up 失败／取消、单次密钥展示、分组 create/edit 回读和按张开关、Grok 诊断与未保存映射、中文／英文、明暗主题、桌面和 320px 手机边界。按 Enter 保存密钥不能提交外层系统设置。非目标页面和认证入口继续通过既有快照与导航帧级检查。

本次不添加 SQL 迁移，不批量修改设置、分组、账号或历史数据。发布仍要求完整测试、精确 main CI、安全证明、同 SHA 双镜像、加密离机备份、实际恢复、新旧镜像兼容、最终停流指纹、Backend-first 切换和至少 30 分钟观察。生产验收只使用受限测试身份；不伪造管理员凭据，不改客户密钥或实际定价来制造成功结果。
