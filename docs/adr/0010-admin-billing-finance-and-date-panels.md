# ADR 0010：管理员实时账单收益与日期浮层（二开保护）

状态：已接受。用户授权新增管理员统计、实时更新、日期选择修复，并要求长期保护二开内容。

## 数据与计算口径

- 四张卡片为今日消费、今日收益、总消费、总收益。消费读取 `actual_cost` 的合计，收益为实际扣费减账号成本，保留亏损和零成本。不是充值金额、标准价，也不包含其他经营费用。
- 2026-09-05 经用户明确要求修正成本来源：账号成本按历史账单 `COALESCE(account_stats_cost, total_cost) * upstream_rate_multiplier` 汇总。`upstream_rate_multiplier` 独立保存请求定价时刻采用的上游声明倍率，包含声明的时区与高峰规则；不读取本地账号倍率，也不依赖同步开关。有效的 0 倍是零成本，保留声明精度，不按本地账号列的四位小数截断。
- 报表使用同一账号最后一次成功取得的声明，直到探测到新的有效声明；探测暂时失败或调度新鲜度过期不清除报表声明。调度仍独立要求新鲜快照。账号凭据、上游地址或代理身份改变时清除旧声明，防止不同上游之间串用。默认探测间隔为五分钟；显式配置、并发限制和上游 `Retry-After` 继续生效，因此倍率变化存在发现延迟。请求使用开始时取得的账号快照，已经开始计价的请求不受之后探测结果影响。
- 没有成功声明、声明只适用于 Token 而请求按次/图片/视频计费，以及缺少当时声明证据的旧账单，成本均为待核算。不能用 1 倍、0 倍、当前声明或当前配置回算旧账。
- 原始 `account_rate_multiplier`、扣费和定价字段保留，仍服务原有本地配额/计费控制；新增声明字段只用于成本报告。迁移不改写历史账单；旧派生汇总列和非空约束保留供旧镜像回滚。旧 `total_account_cost` 继续使用 `zero_one_cost_sum` 传播缺失值，保持接口兼容；新增 `finance` 摘要同时给出已核算／待核算笔数，以及已核算账单对应的实际扣费、成本和收益。部分核算时，收益只用已核算账单的实际扣费减同批成本，不能用全部消费减部分成本。空范围为零；全部缺少依据时收益待确认；部分已有依据时显示已核算结果和待核算数量。每日明细的成本必须遵循同一规则：全部缺少依据时显示待确认，不能把已核算空集合的零合计当作当天零成本。
- 前端不读取当前号池、分组或用户倍率重算历史成本。管理员账单明细、导出、模型/分组统计、账号窗口与仪表盘使用相同声明口径；用户实际扣费和现有配额控制不受本次报表修正影响。
- 每日总 Token 消耗的纵轴、浮层和明细共用 M/B 格式：低于十亿用 M，达到十亿用 B。消费、成本、收益与 Token 展示均保留两位小数；计算和存储保留原精度，只在最终展示时舍入。金额单位保持美元。
- 原管理员 `snapshot-v2` 只作为选中日期范围的来源；它的缓存、UTC 日桶及关闭聚合后的保留窗口不能作为新卡片的实时金额来源。
- 四张卡片和三条每日曲线复用现有管理员 `/admin/usage/stats`，显式传递日期、同一 IANA 时区和 `nocache=true`。今日与曲线中的同一天复用同次响应。总计从 Unix epoch 日期起查询全部**保留账单**，包含超过旧仪表盘窗口的记录；已物理清理的账单不能由 UI 恢复，页面明确说明这一边界。
- 各日期查询是独立的真实后台读操作，不宣称跨请求数据库事务快照。显示的是已经入库的账单，不承诺上游尚未结算或尚未入库的请求已计入。

## 展示边界

四张卡片固定使用“今日消费、今日收益、总消费、总收益”标题；账号成本和部分核算范围放在收益副文案中。保留每日 Token、消费、收益三张趋势图，完整核算说明集中在现有折叠明细中，不增加财务页面、配置或接口。金额继续两位小数，负收益保持可见。

## 实时与失败处理

- 页面可见时，每轮完成后约 30 秒再更新，显示最后完整更新时间；手动重新读取可立即更新。
- 标签页隐藏时停止调度并取消请求，返回前台、恢复网络或恢复页面时立即刷新；不重叠启动刷新。日期、身份或路由改变时取消旧请求，旧结果不得覆盖新选择或泄露给其他身份。
- 总计、今日与每日请求共用最多三个并发名额；单次读取有 20 秒超时。权限失效停止继续请求；至多触发一次原刷新动作，将会话续期交给既有鉴权客户端，不自建续期循环。缺失声明成本显示“待确认”，这与读取失败分开处理；失败日期和读取失败保留缺口及未完整更新状态。
- 新模块为可选 UI，不阻塞登录；图表库只在管理员统计需要时加载。模块晚于原页面初始化完成时，通过原刷新动作补取日期，避免第二套鉴权客户端和第二个仪表盘。

## 日期选择器

恢复版浮层原先把 Vue 所有的日期节点移至 `body`，导致再次打开的节点落在组件观察范围外，无法重新定位。日期节点现在保留原 Vue 父节点，使用浏览器 popover 顶层显示，并通过 Vue 原触发按钮关闭，维护 `isOpen` 与 DOM 的一致性。在 320px 窄屏解除原组件最小宽度冲突，日期输入改为上下排列，保持完整可见。其他下拉面板继续使用原适配路径。

## 长期保护与验收

- 规范实现：`deploy/zero-one/recovered-frontend/console/assets/dashboard-finance-v4/`、`zero-one-floating-panels-v1.js` 及恢复版入口。v1–v3 作为不可变旧资源保留。
- 永久保留：这些规范文件、计算测试、浏览器行为测试、本 ADR 与真实 API 验收脚本逐文件登记在 `.github/upstream-baseline.json` 的 `preserve_on_upstream_sync` 中。
- 视觉保护：管理员财务卡片、三条曲线和日期浮层通过 `.github/scripts/ui-baseline.json` 的受保护界面和不可移动批准标签锁定；普通上游同步不得覆盖。
- `dashboard-finance.test.mjs` 覆盖历史成本、部分核算、负收益、零倍率、两位小数、日界线和时区；Playwright 覆盖反复选日期、取消旧请求、自动刷新、失败保留上次结果、后台暂停、恢复和登录不受可选模块影响。
- `test-dashboard-finance-live.mjs` 只在新建的隔离 PostgreSQL/Redis/Backend/Edge 中造账，走真实 API 和浏览器，验证跨 UTC 午夜、120 天历史账单、修改当前倍率后历史值不变、新旧账混合的部分核算，以及新账单自动刷新可见。退出清理本次资源，不写入已有数据库。
- CI 保留现有全部门禁，并新增以上计算和真实账单验收；不放宽截图阈值。

## 不可变发布资源

上游成本初版使用 `dashboard-finance-v2`；部分核算与两位小数使用 `dashboard-finance-v3`；未知成本修复与简洁展示使用 `dashboard-finance-v4`，旧版本均保留不可变 URL。账号、用量和分布统计的八个恢复版模块只在 `overrides/declared-cost-v1` 维护，由命名空间生成器写入 `cn-provider-shell-v6`；原始批准模块及 v1–v5 命名空间保持原样。生成器校验精确覆盖清单，避免把额外 UI 变化混入发布。新版供应商和生图适配层分别使用 v4、v14，旧版本继续保留，满足不可变缓存和仍打开页面的资源引用。

密码恢复同步生成到 `password-recovery-v2`，复用 v6 的 Vue、Router、API 和 Store；v5 继续引用原 v1，防止跨命名空间混用单例。

版本化适配包中 SHA-256 完全相同的 JavaScript 内容由 `shared-immutable` 保存一份，原 URL 使用相对文件链接，保留各自的模块 URL 与相对导入语义。去重在在线生图构建后的规范步骤执行；闭包与真实 Caddy 响应逐字节验证，不删除旧 URL。
