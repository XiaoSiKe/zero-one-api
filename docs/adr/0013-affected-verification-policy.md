# ADR 0013：按实际影响选择验证范围

状态：已接受。取代 ADR 0004、0008、0009、0012 和既有开发文档中“每个改动都运行全量 Console、后端与视觉套件”的要求；这些记录中的产品行为、历史证据、不可变资源和 Product Change Protection 继续有效。

## 背景

固定 Approved UI Snapshot 后，普通后端或文档修改仍会安装浏览器、重建全部恢复版适配器并比较所有截图。福利码、Mystery Box Redeem Code 等已经验收的独立功能也会在无相关改动时重复执行。最近一次 main 验证中，Console、后端与 Chromium 作业分别约耗时 5 分 40 秒、14 分 46 秒和 8 分 40 秒。

跳过无关验证必须由可审计的路径规则决定，同时保留现有必需检查名称和发布证明。使用 GitHub 的 `skipped` 作业状态不能满足这一合同，因为分支保护和发布者必须区分“经过规则判定不适用”与“本应执行却没有运行”。

## 决策

`.github/test-impact-policy.json` 是影响规则的唯一维护位置，`.github/scripts/select-test-impact.mjs` 是唯一解释器。Pull Request 使用 base 与 head 的完整三点差异；main push 使用 before 与 head；重命名和复制同时检查旧、新路径。缺少历史、未知路径、规则或工作流自身变化都回退到完整验证。

每个现有必需作业仍然启动，并在成功结果中留下“required”或“not applicable”两条互斥步骤证据。需要执行的步骤失败、取消或缺失时，作业失败；不适用时只运行低成本判定。发布者检查当前 main push 的成功作业及互斥影响证据，不接受普通 skipped、旧 attempt 或另一提交的结果。

后端按 `redeem`、`data`、`gateway` 和 `full` 四种范围选择普通、unit 与 integration 构建标签。不同后端范围同时出现时扩大到 `full`。Console 行为验证与恢复版适配器生成分别选择；API 类型或单元测试变化不触发全部适配器生成。

视觉范围为 `none`、`dashboard` 或 `full`。UI 未受影响时只校验 Approved UI Snapshot 的提交、资源引用和保护边界，不启动浏览器。仪表盘局部改动运行目标页面的桌面、手机合同；公共壳层、路由、共享样式、渲染依赖或无法可靠归类的 UI 改动运行全量视觉套件。上游前端文件只有进入实际交付资源或受保护源码时才构成 UI 影响。

依赖锁文件触发对应生态的安全检查；每周 Security Scan 始终完整执行。Docker、Caddy、迁移和部署脚本触发交付验证。福利码、Mystery Box Redeem Code 只在其自身路径，或用户余额、事务、鉴权等共享依赖变化时执行；共享影响合并为更宽范围。

本地 `make test-affected` 使用同一解释器，并把未提交路径加入选择。`make test` 和手动诊断工作流继续提供显式完整验证入口。本决策不降低测试断言、截图阈值或错误处理要求。

## 后果

Product Change Protection 继续回答“上游同步必须保留什么”，影响规则回答“当前差异需要验证什么”。永久保护不再等价于每个 PR 重跑该功能的全部历史测试。

本策略首次合入时运行完整基线。以后修改选择器、策略、产品工作流或发布证明时也必须完整运行，防止规则用自身规则跳过验证。
